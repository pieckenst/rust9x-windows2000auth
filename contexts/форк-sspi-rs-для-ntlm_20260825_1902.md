```text
        └── sspi fork
```

Это уже фактически один portability stack.

3. **Можно менять внутренние API без публикации релиза.**

Например, тебе захочется добавить в `sspi-rs` какой-нибудь:

```rust
pub fn set_workstation_name(...)
```

или конфигурацию:

```rust
NtlmConfig {
    workstation,
    ...
}
```

и `rust9x-windows2000auth` сразу это использует.

4. **Не придётся воевать с совместимостью версий.**

Особенно важно, потому что твой `sspi 0.21.3` уже имеет довольно свежие зависимости. В lockfile видно, что он тянет современный crypto/dependency stack, который сам по себе может стать проблемой для твоих древних target'ов. fileciteturn27file0L2-L2

И здесь я бы даже пошёл немного дальше.

### Я бы сделал `third_party`

Чтобы основной `src` не превратился в свалку:

```text
rust9x-windows2000auth/
└── rust-src/
    ├── src/
    ├── Cargo.toml
    ├── Cargo.lock
    │
    └── third_party/
        ├── sspi-rs/
        ├── schannel-rs/
        └── native-tls/
```

Тогда:

```toml
[dependencies]
sspi = { path = "third_party/sspi-rs" }
native-tls = { path = "third_party/native-tls", optional = true }
```

А внутри `native-tls`:

```toml
schannel = { path = "../schannel-rs" }
```

Получается полностью замкнутый dependency graph:

```text
rust9x-windows2000auth
│
├── sspi-rs
│   └── свои зависимости
│
└── native-tls
    └── schannel-rs
        └── Windows legacy compatibility
```

И тогда твой репозиторий становится не просто «DLL с NTLM», а реально:

> **Rust authentication/TLS compatibility layer for Windows 2000/9x-era environments**

Причём это ещё и сильно удобнее для твоего forked `sspi-rs`: можно спокойно делать commits вроде:

```text
sspi: restore Windows-compatible NTLM workstation field
sspi: fix NTLMv2 negotiated flags
sspi: improve local-account NTLM interoperability
sspi: legacy target compatibility
```

и тестировать всё непосредственно из `rust9x-windows2000auth`.

Единственное, что я бы **не делал** — копировать исходники `sspi-rs` прямо внутрь `src/sspi/` и превращать их в часть одного crate. Лучше оставить его отдельным Cargo package и подключать через `path`. Так ты сохраняешь нормальную границу crate и при этом получаешь полный локальный контроль.

И да — с учётом того, что у тебя уже локально лежат fork'и `native-tls`/`schannel`, **локальный fork `sspi-rs` сюда ложится совершенно органично**, а не выглядит каким-то костылём. fileciteturn5file0L1-L6
