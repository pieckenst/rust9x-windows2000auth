# Самая подозрительная вещь — HTTP 400

Вот это принципиально:

```text
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Negotiate TlRMTVNTUAAC...
```

после Type 1 — совершенно нормальный этап NTLM.

А вот:

```text
Authorization: Negotiate TlRMTVNTUAAD...
```

→

```text
HTTP/1.1 400 Bad Request
```

уже ненормально.

Причём 400 особенно интересен потому, что **Kestrel сам умеет возвращать 400 при отбрасывании HTTP-запроса на уровне parser**, ещё до того как запрос попадёт в ASP.NET middleware. Для таких отказов у него есть отдельный `Microsoft.AspNetCore.Server.Kestrel.BadRequests` logger. citeturn817553search1

Но в твоём случае есть одна важная деталь:

> Kestrel уже успешно распарсил весь HTTP-запрос и смог вернуть нормальный HTTP response по TLS.

Поэтому нам нужно выяснить, **400 сгенерировал именно Kestrel parser или уже приложение/middleware**.
